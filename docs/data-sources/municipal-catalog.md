# Catálogo Municipal de Fontes de Dados Públicos

Este catálogo reúne fontes de dados abertos municipais e estaduais mapeadas a partir de pesquisa estruturada (pack ChatGPT, junho 2026). As fontes têm status `catalogued` — mapeadas, ainda não ingeridas pela plataforma. Use-as como backlog de expansão ao iniciar o módulo `municipios`.

## Padrões de descoberta

### CKAN municipal

Como detectar: Testar `/api/3` e `/api/3/action/status_show` no domínio do portal.

Endpoint típico: `/api/3/action/package_search?q=licitacao&rows=10`

Risco: Nem todo recurso tem DataStore; muitos links são arquivos soltos.

### APILIB / vitrine municipal

Como detectar: Buscar 'api', 'vitrine de APIs', 'developer', 'swagger' no domínio da prefeitura.

Endpoint típico: varia por API

Risco: Pode exigir chave, cadastro ou estar parcialmente homologada.

### PortalTP

Como detectar: Buscar domínio `*-uf.portaltp.com.br/api/dadosabertos.aspx`.

Endpoint típico: `/api/dadosabertos.aspx` e endpoints listados na página.

Risco: Padrão de endpoints varia; precisa crawler por página.

### Kingpage / API dados-abertos

Como detectar: Buscar `/api/dados-abertos/dados?modulo=` no site municipal.

Endpoint típico: `/api/dados-abertos/dados?modulo=licitacao&ano=2026`

Risco: Módulos variam por município.

### WebService transparência legislativo

Como detectar: Buscar `/transparencia/api/webservice`.

Endpoint típico: `?type=json&page=1&page_size=100`

Risco: Pode ter limite de página e campos antigos.

### TCE/TCM estadual

Como detectar: Buscar "TCE UF API dados abertos municípios".

Endpoint típico: varia por tribunal.

Risco: Dados podem atrasar e dependem do envio dos jurisdicionados.

### ArcGIS / Open Data

Como detectar: Buscar 'portalgeo', 'opendata.arcgis.com', 'FeatureServer'.

Endpoint típico: `/arcgis/rest/services/.../FeatureServer/0/query?where=1=1&f=json`

Risco: Limites por consulta e geometria pesada.

### NFS-e Nacional

Como detectar: Usar docs oficiais gov.br/nfse.

Endpoint típico: ADN / parametrização / municípios / contribuintes.

Risco: Não é dado aberto geral; costuma exigir certificado/credencial.

## Buscas prontas

1. `site:{dominio_prefeitura} api dados abertos` — Achar API oficial no site do município
2. `site:{dominio_prefeitura} /api/3/action package_search` — Detectar CKAN
3. `"{cidade}" "api/dadosabertos.aspx"` — Detectar PortalTP
4. `"{cidade}" "api/dados-abertos/dados"` — Detectar API Kingpage
5. `"TCE-{UF}" "API Dados Abertos" municípios` — Achar fonte estadual de controle externo
6. `"{cidade}" "FeatureServer" prefeitura` — Achar geodados ArcGIS
7. `"{cidade}" "licitações" "api" prefeitura` — Achar API de licitações
8. `"{cidade}" "diário oficial" "dados abertos"` — Achar diários e PDFs

---

## Pipeline sugerido (9 etapas)

1. Criar cadastro base dos 5.570 municípios via IBGE (IBGE Localidades API) — sem isso o resto vira bagunça de nomes.
2. Rodar descoberta de portais por município (domínios + padrões) — usar crawler leve e respeitoso.
3. Classificar tecnologia (CKAN, PortalTP, Kingpage, ArcGIS, WebService, Arquivo, PDF) — a tecnologia define o coletor.
4. Validar endpoint básico (GET status/list/módulos) — guardar HTTP status e data.
5. Coletar metadados primeiro (package_list, módulos, links) — catalogar antes de baixar tudo.
6. Baixar dados brutos (raw_json, raw_csv, raw_pdf, raw_xlsx) — salvar imutável.
7. Normalizar chaves (cidade_uf, código IBGE, órgão, data, CNPJ, fornecedor) — essencial para cruzar fontes.
8. Extrair PDFs quando necessário (editais, contratos, diários oficiais) — PDF é o porão da burocracia.
9. Gerar alerta de oportunidades (licitação/contrato/obra/empresa/edital) — aqui vira produto.
